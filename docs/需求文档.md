# lostwall — 音乐节防丢壁纸 需求文档 v0.4

> 状态：v1 已实现并上线 https://nex627.github.io/lostwall/
> 日期：2026-11-15
> 仓库：https://github.com/nex627/lostwall
> 来源：待办事项「个人兴趣 / 新玩意」下的 `[ ] 音乐节防丢壁纸`，2026-10 记录，一直未动

---

## 1. 一句话

**选一张音乐节海报（或者你自己拍的现场），用大字印上"捡到请联系 138 8888 8888"，设成锁屏——手机丢了，捡到的人不用解锁就知道打给谁。**

## 2. 要解决的具体场景

不是"防丢"，是**丢之后那 5 分钟**：

```
音乐节散场，人挤人，手机从兜里没了。
捡到的人拿到一台锁屏手机：
  ├─ 有密码，进不去
  ├─ 不知道是谁的
  └─ 手机静音，也没法等来电
→ 大概率交给保安 / 塞进包里 / 放原地
```

现有的解法都不合适：

| 方案 | 问题 |
|---|---|
| 手机壳里塞张纸条 | 得先想到、得写字、换号要重写 |
| 锁屏留"医疗急救卡" | 入口深，捡到的人不知道去那儿看 |
| 苹果"查找"App | 要另一台设备 + 失主主动操作，捡到的人不会用 |
| 挂个防丢牌 | 牌在包上，手机单独丢了没用 |

壁纸是**唯一一个不用解锁、不用装东西、一按电源键就看见**的位置。

## 3. v1 做什么

### 3.1 三条入口（同一套渲染，只是底图来源不同）

```
① 通用款   → 纯色 / 渐变底，不要任何素材，10 秒出图（零门槛，默认页）
② 音乐节   → 选音乐节 → 代码把名称/城市/年份/日期排成海报 → 加号码
③ 自己的照 → 上传现场照 → 加号码

三条都汇到同一个出口：填号码 → 预览 → 导出 → 设为锁屏
```

### 3.2 功能清单

| # | 功能 | 说明 |
|---|---|---|
| F1 | 上传照片 | jpg / png / webp / heic，本地读取，不上传 |
| F2 | 内置模板 | 6 张无版权抽象纹理（自绘 / CSS 渐变），给没现场照的人兜底 |
| F3 | 号码输入 | 必填 1 个 + 选填 1 个，中国大陆 11 位校验。**必须是"另一台手机"的号**（见 §5.3） |
| F4 | 备注一行 | 选填，限 24 字，如"内有工作资料，麻烦联系" |
| F5 | 号码排版 | **号码字号 = 屏宽 × 8%（下限 6.5%）**，3-4-4 分组，等宽数字。3 套底色：黑底白字 / 白底黑字 / 半透明黑 |
| F6 | 位置微调 | 上 / 中 / 下三档预设（默认"中"，见 §5.1） |
| F7 | 比例预设 | 19.5:9（默认）/ 20:9 / 16:9 / 自定义裁剪 |
| F8 | 实时预览 | 所见即所得，带锁屏模拟框（时间 + 通知占位） |
| F9 | 导出 | 输出 PNG，长边 2556px，浏览器本地 Canvas 生成 |
| F10 | 本地记住 | localStorage 存上次的号，下次打开自动填（可一键清除） |
| F11 | 音乐节模板 | 内置 8 个音乐节（名称 / 城市 / 年份 / 日期），代码排成海报底。**不内置阵容**（见 §7.7） |
| F12 | 通用底 | 3 款纯色 / 渐变底，无需任何素材，默认入口 |

**手机号"自由编辑"的含义**：改号 = 改输入框 → 重新导出一张 → 重新设壁纸。约 30 秒。**不是壁纸上实时可变**，原因见 §7.2。

### 3.4 时间与地点：怎么"推荐"

**前提：数据里只有"惯例"，没有"本年官宣"**（理由见 §7.7 —— 我们不能编日期）。

所以每条音乐节记录三样：`名称 / 常见城市 / 惯例月份`。

**排序规则：**

1. 先按城市筛（顶部一个城市切换：全部 / 北京 / 上海 / 成都 / 温州 / 秦皇岛）。
2. 按「距离下一次惯例月份还有多久」升序。
3. **只列有真实节目单的场次。** 查不到逐组时刻的音乐节**不进列表** —— 一张没有时间表的海报，对乐迷没有价值，只是占位。
4. **已结束但有节目单的保留**，明确标「2025 已结束 · 纪念款」。不假装它还没结束。
5. 列表为空时退回**通用款**，任何时点都能用，保证不出现空面板。

**一个必须面对的现实：**

现在是 11 月。国内大场基本收官，2027 赛季还没官宣。加上"只列有节目单的"这条过滤，
**此刻列表里只有一场**：2025 长沙草莓。

这不是数据坏了，是现实：能核实的逐组时间表本来就屈指可数，且都发生在过去。
处理方式：就把它当测试样例默认选中，标「纪念款」，下面对应一句
「只列有真实节目单的场次；往届的标出来，做纪念款一样能用」。

**不塞垃圾场次充数，也不装出"有很多场"的样子。**

### 3.5 节目单：海报上的「几点几分哪个乐队」

选了音乐节之后，可以把**真实的演出时刻表**排进海报：按天分列，每列一行「20:40 痛仰」。

**这一节的核心不是排版，是数据可信。**

| 规则 | 具体做法 |
|---|---|
| **数据必须带年份** | 每条节目单必须有 `year` + `source`。海报上印的日期就是数据本身的日期 |
| **绝不冒充今年** | `year: 2025` 的数据，海报上一定印 `2025.06.01 – 06.02`。拿去年阵容贴今年标签是这个项目唯一一处"一眼就被看穿"的错 |
| **不推断、不补全** | 只收录查得到的组和时刻。喜鹊舞台没查到就写"未收录"，不按规律猜 |
| **不联网** | 数据是静态文件，粘贴的节目单只在本地解析。没有请求、没有接口、没有代理 |

**内置数据现状（诚实版）：**

只内置了**一份**完整节目单 —— 2025 长沙草莓音乐节·草莓舞台，两天 24 组。

原因：国内音乐节的分钟级时间表几乎只以**图片海报**发布。2024 台州迷笛、2025 阿那亚虾米这类只能查到「按日阵容 + 舞台开场/收场时间」，查不到逐组开演时刻。文字版能核实的样本极少，**不硬凑，也不自己编一份填进去。**

**其余音乐节的两条路：**

1. **粘一份**：界面上有输入框，照着官方图片敲进去，解析器认 `20:40-21:30 痛仰` / `20:40 痛仰` / `痛仰 20:40-21:30` 三种写法；没有时间的行当日期分段。解析在本地，不猜。
2. **等 v2**：GitHub Action 定时抓官网 → 静态 JSON，依然不给网页端引入后端。

**排版约束（与 §5.1 联动）：** 节目单是**装饰**，号码是**功能**。所以节目单永远排在号码块之外的空区；空间不足以让乐队名达到屏宽 2.5% 时，**宁可不印**，也不印成一排米粒大的字。号码块位置（上/中/下）会决定节目单落在它上方还是下方，代码取空地更大的一侧。

## 4. 不做什么（边界）

| 不做 | 为什么 |
|---|---|
| 账号 / 登录 / 云同步 | 一旦有后端就得存手机号，与"开源 + 隐私"直接冲突 |
| 服务器生成图片 | 同上，且白送服务器成本 |
| 原生 App / 小程序 | 上架审核、签名、更新，为一张图不值当 |
| 动态壁纸 / 锁屏小组件 | iOS 需写 SwiftUI Widget 并过审，Android 各家 API 不统一，3 天变 3 周（见 §7.2） |
| 定位 / 追踪 / 响铃 | 那是「摇滚电子旗帜」的活，不要混进来 |
| 付费 / 会员 / 广告 | 开源工具，v1 不谈钱 |
| 内置真实音乐节现场照 | 版权风险。只用自绘纹理 + 用户自己上传 |
| 自动抓阵容 / 时间表（爬虫） | 纯前端抓不了、每年要维护、且不能编假数据，见 §7.7。**人工核对的静态数据 + 用户粘贴**是 v1 的路，不是爬虫 |
| 多语言 | v1 只做中文 |

## 5. 硬约束（这是产品能不能真起作用的关键）

### 5.1 锁屏安全区 — 最高优先级

壁纸好不好看是次要的，**信息有没有被遮住是生死线**。

实测 iOS 15/16/17 锁屏布局（占屏幕高度约）：

```
0%   ┌─────────────────┐
     │                 │
18%  │   09:41 大字    │  ← 时间区
28%  │                 │
     │  ★ 安全带 ★     │  ← y=28%~36%，时间下方、通知上方
33%  │                 │
     │  ┌───────────┐  │  ← 通知从这里开始堆，会盖住更多
50%  │  │ 微信 2 条  │  │
     │  └───────────┘  │
80%  │                 │  ← 底部安全带 y=78%~88%
92%  │  🔦      📷     │  ← 手电筒 / 相机，不可压
100% └─────────────────┘
```

**规则：**
1. 信息带默认放 **y = 28%~36%**。这是唯一"按电源键就能看见、且通知堆不满"的位置。
2. 信息带必须自带**不透明底色块**，不能只靠文字压图——否则照片一亮（舞台光）字就没了。
3. **Always-On Display 会把壁纸压暗约 80%**，文字与底色对比度必须 ≥ 4.5:1。
4. 上下左右各留 **8% 安全边距**——iOS 设壁纸有"透视/缩放"，边缘会被吃掉。
5. Android 各家锁屏差异大（时间可能居左 / 居中 / 居中偏上），信息带放下 1/3 更稳，供 F6 切换。

### 5.2 号码必须大 — 这是明确的设计选择

**优先级：能在三米外一眼读出来 > 画面和谐。** 号码就是这张壁纸的主体，照片退成背景。

| 元素 | 字号 | 参照（iPhone 15 Pro，屏宽 1179px） |
|---|---|---|
| 号码 | 屏宽 × **8%**（下限 6.5%） | 94px，≈ 锁屏时间大字大小 |
| 前缀「捡到请联系」 | 屏宽 × 3.2% | 38px，比号码小一半，不抢戏 |
| 备注（选填） | 屏宽 × 2.4% | 28px，只做补充 |

**配套规则：**
- **3-4-4 分组**：`138 8888 8888`，人眼识别最快，也避免 11 位连读看错。
- **等宽数字**：`font-variant-numeric: tabular-nums`，防止数字宽度跳动。
- 号码底色块高度 = 字号 × 1.6，保证不被裁切。
- **代价要知道**：号码占掉屏幕宽度的 80%+，照片主体必须在上半部分，否则被压。上传时提示一句"号码会压在下半部分，选一张主体偏上的图"。

### 5.3 号码归属 — 最容易做错、做错就白做的一条

**如果壁纸上的号 = 这台手机自己的号，捡到的人打过去，响的是他手里这台。死循环。**

所以：

- 输入框标签写 **「能联系到你的号码」**
- 副文案写 **「不要填这台手机的号 —— 填家人、备用机或同事的」**
- 系统无法自动识别"你填了自己的号"（浏览器不知道本机号码），只能靠文案 + 导出后的一句确认：
  > 「确认一下：这个号不是你现在手里这台手机的吧？」
- v1 支持 1 个必填 + 1 个选填（第二个通常是另一个家人）
- 只有一台手机的人 → 提示"填朋友或同事的号，也可以"

这一条不写清楚，产品就是"看着能用、真丢了没用"。

### 5.4 其他约束

- **不遮挡人脸**：上传人像/舞台正面时，给三档位置预设让用户挪（v1 不做人脸识别）。
- **深色模式友好**：默认样式在 AOD 与浅色壁纸下都要可读。
- **首屏 3 秒可用**：不做引导页、不做注册墙，进来就是上传框。

## 6. 技术形态

| 项 | 选择 | 理由 |
|---|---|---|
| 形态 | **纯前端静态站，单页** | 零后端 = 零隐私风险 = 零成本 = push 就能托管 |
| 栈 | **原生 HTML + 原生 JS (ESM) + Canvas 2D，零依赖零构建** | 一个页面而已。不引入 Vite/npm，改一行 push 就生效 |
| 图像处理 | 浏览器本地 Canvas，`toBlob('image/png')` | 照片和号码不出本机 |
| 状态 | localStorage 仅存"上次的号 + 样式" | 明示可清空，不存照片 |
| 托管 | **GitHub Pages，仓库根目录直接发布** | 你要的免费站，无 Actions、无 secrets |
| 分站镜像 | **https://ciyuannav.com/lostwall/**（已上线 2026-11-16，CloudBase 静态托管，`scripts/deploy-ciyuannav.sh`） | 主站引流位；产物在 `.deploy/`，不重复维护 |
| 网址 | `https://nex627.github.io/lostwall/` | 项目页带子路径 |
| 协议 | MIT | 开源，随便用 |
| 目录 | `index.html` + `src/` + `assets/` + `docs/` | 平铺，简单到不用讲 |

**GitHub Pages 的一个坑（必须提前处理）：**
项目页的地址带子路径 `/lostwall/`，所以 HTML 里所有资源引用**必须用相对路径**（`./src/app.js`），不能用 `/src/app.js`——用绝对路径会在 GitHub Pages 上全部 404。本地双击 `index.html` 也得能跑，所以不用任何需要服务器的东西。

**已知摩擦点（是现实，不是 bug）：**
- iOS Safari **不能直接下载到相册**，只能长按图片 → "存储到照片"。导出后必须给明确指引，否则用户以为没成功。
- 微信内置浏览器**保存图片受限**。检测到微信 UA 时提示"右上角 → 在浏览器打开"。

## 7. 被否掉的方案及理由

### 7.1 后端生成图片
否。用户上传照片 = 服务器拿到你的现场照 + 号码；一旦开源，别人自建实例就意味着谁都能看到数据。为一个 PNG 引入隐私负债和服务器账单，不值。

### 7.2 做成锁屏小组件 / 动态壁纸（"自由编辑"到底指什么）
否（v1）。
- iOS 16+ 有锁屏 Widget，能动态显示文本——但**必须写 App、签名、过审、99 美元/年**，用户还得装 App。把"打开网页 30 秒"变成"下载安装授权"，转化率掉一个数量级。
- Android 没有统一的锁屏文字 API，各家 ROM 方案不同，只能靠 KWGT 这类第三方，体验不可控。
- **结论**：静态图 + 重新生成，是"改号"这个低频动作的最优解。真要动态，那是 v3，且大概率该并进「摇滚电子旗帜」。

### 7.3 做成小程序
否。保存图片要授权相册，分享链路会把它变成"社交产品"。这东西的价值在"自己用"，不在传播。

### 7.4 内置音乐节现场图库
否。演出照片版权归属复杂（摄影师 / 主办方 / 乐队），开源项目内置侵权图是给自己埋雷。改为：自绘抽象纹理兜底 + 鼓励上传自己拍的。

### 7.5 做成二维码防丢牌
否。`petqr` 做过，且二维码在锁屏上看不见，救不了"捡到手机"这个场景。

### 7.6 上 Vite / React
否。一个页面 + 一次 Canvas 绘制，构建链带来的只有维护成本。**零构建 = 你随时能在 GitHub 网页上直接改一行**，这对手握十几个项目的人来说比类型安全更值钱。

### 7.7 自动抓演出时间表 / 代码生成 lineup
否（v1），这一条后来**实地验证过**，不是纸上推断。三条，按重要度排：

1. **纯前端抓不了。** 秀动、大麦、摩登天空这些站点不带 CORS 头，浏览器里 `fetch` 直接失败；要绕过就得自建代理服务器——又绕回"有后端"，正好撞上 §7.1。
2. **数据每年变。** 阵容、日期、场地年年不同，页面一改版抓取规则就废。维护这个爬虫的成本，比工具本身还高。
3. **不能编。** 阵容是事实。代码可以排版，但绝不能生成假的乐队和假的时间——开源项目里放假 lineup，被乐迷指出一次就废了。

**实地查证的结果（2026-11-15）：** 逐条检索了迷笛、草莓、简单生活节、阿那亚虾米等，
**分钟级的逐组时间表几乎只存在于官方发布的图片海报里**。文字版能拿到的只有两种：
「按日阵容名单」和「舞台开场/收场时间」。唯一查到完整逐组时刻的是 2025 长沙草莓音乐节。

→ **v1 的做法（已实现）**：
- 内置**一份**人工核对过的完整节目单（2025 长沙草莓，带 `source` 和 `year`）；
- 其余音乐节只放名称 / 城市 / 惯例月份，海报照排；
- 用户可**粘贴**自己的节目单，本地解析成同样的排版。

→ **v2 再考虑**：GitHub Action 定时抓官网 → 生成静态 JSON。这样既有数据，又不给网页端引入后端。
但前提是官网本身发文字版；如果永远只有图片，那 v2 也不做，粘贴这条路就是终局。

## 8. 错误码

纯前端，错误码用于统一文案（无后端日志）。

| Code | 触发 | 用户看到的话 | 处理 |
|---|---|---|---|
| `E01` | 图片格式不支持（gif / bmp / raw） | 只支持 JPG / PNG / WebP / HEIC，换一张试试 | 阻止导入 |
| `E02` | 图片 > 20MB | 图片太大了，压一下再传 | 阻止导入 |
| `E03` | 图片解码失败（损坏 / HEIC 不支持） | 这张图打不开，换一张 | 提示改用 JPG |
| `E04` | 号码不足 11 位 / 含非数字 | 号码填 11 位数字 | 输入框标红，禁用导出 |
| `E05` | 备注超 24 字 | 备注最多 24 个字 | 截断并提示 |
| `E06` | Canvas 创建失败（内存不足） | 图太大，浏览器处理不了，换张小点的 | 建议缩到 4000px 内 |
| `E07` | `toBlob` 返回 null | 导出失败，刷新页面重试 | 提供"降低分辨率重试" |
| `E08` | 浏览器不支持 Canvas / FileReader | 建议用 Chrome / Safari 最新版 | 显示降级说明 |
| `E09` | 微信内置浏览器 | 右上角「…」→ 在浏览器打开 | 顶部横条提示 |
| `E10` | 粘贴的节目单一行时间都没认出来 | 没认出时间 —— 每行写「20:40-21:30 乐队名」 | 不切换，保留原节目单 |

## 9. 验证与退出条件
